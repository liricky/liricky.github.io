Python 中可变对象和不可变对象有什么区别，函数默认参数为什么容易踩坑？

  • 知识点：Python 对象模型。
  • 解析：可变对象（如 list, dict, set）创建后可以修改内容；不可变对象（如 int, str, tuple）不能修改。默认参数踩坑是因为：函数默认参数在函数定义时（def 语句执行时）只被评估一次。如果默认参数是可变对象，那么多次调用该函数时，所有调用都会共享同一个默认对象。如果函数内部修改了它，后续调用会受到影响。
  • 避坑：默认参数使用 None，并在函数内部判断：if param is None: param = []。

Python 的深拷贝和浅拷贝有什么区别，如何避免嵌套配置被意外修改？

  • 知识点：Copy 模块。
  • 解析：
    • 浅拷贝（copy.copy()）：只复制最外层对象，内部嵌套的列表/字典仍指向同一个引用。
    • 深拷贝（copy.deepcopy()）：递归复制所有层级的对象，完全独立。
    • 避免嵌套配置被修改：使用 copy.deepcopy() 进行配置拷贝；或者使用不可变数据结构（如将字典转为 MappingProxyType，或使用 pydantic 的不可变模型）来限制修改。

第1题：什么是协程，它和线程有什么区别？

协程是一种用户态的轻量级并发执行单元，其调度由程序自身控制，而非操作系统内核。线程是操作系统进行CPU调度的基本单位，由系统抢占式调度。

核心区别：

维度 线程 协程
调度者 操作系统内核 用户程序（事件循环）
切换开销 高（需保存/恢复TCB） 低（用户态直接操作栈）
资源消耗 较高（独立栈） 极低（共享线程资源）
并发模型 抢占式多任务 协作式多任务
是否需要锁 需要（共享可变状态） 通常不需要

上下文保存方面，线程的上下文保存在任务控制块中，每次切换都会消耗资源；协程将寄存器上下文和栈保存到用户空间，直接操作栈几乎没有内核切换开销。协程并非取代线程，而是抽象于线程之上——线程是被分割的CPU资源，协程是组织好的代码流程，协程需要线程来承载运行。每个协程消耗的资源少于线程或进程。

延伸知识点： Python中协程的实现基于生成器，通过async/await语法支持。Python原生支持三种执行单元：进程、线程和协程。线程和协程的编程模型几乎相同，差异在于asyncio中所有可能阻塞的函数必须标记async，所有调用必须标记await，且协程可以被终止而线程不能。

第2题：with语句了解么？

with语句是Python中用于简化try/finally标准用法的语法结构，其核心目的是确保资源在使用后能被正确释放。上下文管理器提供__enter__()和__exit__()方法，分别在进入和退出with语句主体时被调用。

执行流程：

  1. 执行context_expression生成上下文管理器对象
  2. 调用__enter__()方法，返回值赋给as子句中的变量
  3. 执行with语句块内的代码
  4. 无论是否发生异常，均调用__exit__()方法完成清理

延伸知识点： 也可以通过contextlib.contextmanager装饰器将生成器函数转换为上下文管理器，简化实现。__exit__()的返回值决定是否抑制异常：返回True表示异常已被处理，返回False或None则异常继续传播。

第3题：Python中列表和元组的区别？

核心区别在于可变性： 列表是可变的，元组是不可变的。

性能差异：

  • 元组的生成速度比列表快得多，相差约一个数量级，且迭代速度略快
  • 列表在需要动态调整大小时会涉及内存重分配和拷贝，元组不需要，因为其大小固定
  • 元组通常比列表使用更少的内存

使用场景：

  • 列表适用于需要频繁修改、增删元素的场景
  • 元组适用于数据不应被修改的场景，且可作为字典的键（可哈希）

延伸知识点： 元组可以作为函数的多个返回值，这本质上是返回了一个元组。在CPython中，元组对象有优化（如空元组的单例复用），使其性能优于列表。

第4题：深拷贝、浅拷贝？用什么方法实现？

浅拷贝（copy.copy()）创建一个新的容器对象，但嵌套对象的引用保持不变——修改浅拷贝中的嵌套可变对象会影响原始对象。深拷贝（copy.deepcopy()）递归复制对象的所有层级，为每个可变子对象创建独立副本，确保完全独立。

实现方法：

拷贝方式 方法 说明
浅拷贝 copy.copy(obj) 仅复制顶层对象
浅拷贝 list(original) / original[:] 列表的切片和构造函数
深拷贝 copy.deepcopy(obj) 递归复制所有层级

自定义拷贝： 类可以定义__copy__()和__deepcopy__()方法来实现自己的复制逻辑。__deepcopy__()接受一个memo字典参数，用于跟踪已拷贝的对象，避免循环引用导致的无限递归。

延伸知识点： 深拷贝的性能开销远大于浅拷贝，对于仅包含不可变对象的对象（如全字符串元组），浅拷贝与深拷贝效果相同。多线程环境下，深拷贝可以避免共享状态的意外修改。

第5题：迭代器和生成器区别？

迭代器是实现了__iter__()和__next__()方法的对象，遵循迭代器协议。生成器是一种特殊的迭代器，使用yield语句产生值，自动实现了迭代器协议。

核心区别：

维度 迭代器 生成器
创建方式 类实现__next__() 函数中使用yield
代码简洁度 较复杂 简洁
状态保持 需手动管理 自动保持函数执行状态
可重用性 可自定义 不可重用（耗尽后停止）

生成器一定是迭代器，但迭代器不一定是生成器。列表、字典、字符串是可迭代对象（Iterable），但不是迭代器（Iterator），因为它们是惰性循环的。生成器因为自动创建了__iter__()和__next__()方法，显得特别简洁且高效，同时节省内存。

延伸知识点： 生成器表达式(x**2 for x in range(10))比列表推导式[x**2 for x in range(10)]更节省内存，因为前者是惰性求值。yield from语法可以委托给子生成器。

第6题：Python的subprocess库是什么？什么是进程？什么是协程？

subprocess库用于创建和管理子进程，允许Python程序运行外部命令和程序。asyncio提供了高层级的async/await API来管理子进程，所有asyncio子进程函数都是异步的。

进程是操作系统进行资源分配和调度的基本单位，每个进程拥有独立的地址空间、文件描述符和系统资源。

协程是一种用户态的轻量级并发执行单元，由程序自身调度，与线程的抢占式调度不同。

三者的资源消耗关系： 进程 > 线程 > 协程。每个协程消耗的资源少于线程或进程，线程消耗的资源少于进程。

第8题：Python的multiprocessing和threading如何结合使用来提高整体吞吐量？

核心策略： 对于I/O密集型任务使用多线程（threading或ThreadPoolExecutor），对于CPU密集型任务使用多进程（multiprocessing或ProcessPoolExecutor），两者结合可以最大化吞吐量。

GIL的影响： GIL是CPython解释器的互斥锁，同一时间一个进程内只有一个线程能执行Python字节码。I/O操作（文件读写、网络请求）会主动释放GIL，因此多线程对I/O密集型任务有效；CPU密集型任务则受限于GIL，多线程无法利用多核CPU。

实验数据： 有研究者用RSA加密算法测试，在6核机器上，1个线程耗时约1.98秒，6个线程耗时约2.1秒，几乎无提升；而6个进程实现了接近5倍的加速。CPU密集型任务中，4线程方案比单线程还慢约0.52秒，多进程则实现线性加速。

第10题：asyncio.gather和asyncio.as_completed在并发请求多个模型接口时有什么区别？如果其中一个接口超时，如何做降级？

核心区别：

维度 asyncio.gather asyncio.as_completed
返回顺序 与输入顺序一致 按完成顺序返回
返回方式 一次性返回所有结果 迭代器逐个返回
适用场景 需要有序结果 流式处理、尽早展示
异常处理 一个失败默认整体抛出 逐个处理异常

asyncio.gather并发执行所有任务并按输入顺序返回结果；asyncio.as_completed返回一个迭代器，按任务完成顺序产出结果。使用gather时，如果任一协程抛出异常，整个操作会立即抛出异常并取消剩余任务；使用return_exceptions=True可以让所有任务完成并收集异常。

降级策略建议：

  1. 使用asyncio.wait_for为每个任务设置独立超时
  2. 结合return_exceptions=True收集所有结果（包括异常）
  3. 对超时的接口返回默认值或调用备用轻量级模型
  4. 如果关键接口超时，可使用asyncio.wait的FIRST_COMPLETED模式，一旦有可用结果就先返回

延伸知识点： Python 3.11+引入了asyncio.TaskGroup，提供了结构化并发，在异常时会自动取消所有任务。对于LLM场景，as_completed适合流式输出（用户先看到部分结果），gather适合需要完整有序结果的批量处理。

第11题：Python中的GIL锁？

GIL（全局解释器锁）是CPython解释器为保证内存安全引入的互斥锁，核心规则是“同一时间，一个进程内只有一个线程能执行Python字节码”。

为什么存在？ Python使用引用计数进行内存管理，多个线程同时修改引用计数可能导致计数错误和程序崩溃。GIL用一个全局锁简化了内存管理的复杂度。

GIL对不同任务的影响：

  • CPU密集型任务： GIL导致多线程无法利用多核CPU。多个线程争抢GIL造成性能内耗，甚至比单线程更慢。实验表明，6线程RSA计算与单线程耗时几乎相同（约2秒），而6进程可实现接近5倍加速。
  • I/O密集型任务： I/O操作会主动释放GIL，其他线程可趁机执行，因此多线程或异步IO能显著提升吞吐量。

绕过GIL的方案：

  1. 多进程（multiprocessing） ：每个进程有独立的Python解释器和GIL，可实现真正的并行
  2. C扩展（如NumPy） ：在C层面释放GIL
  3. asyncio：单线程内通过事件循环实现并发，避免GIL争抢
  4. Python 3.13+无GIL模式：实验性特性，尚未生产就绪

延伸知识点： GIL是CPython解释器的特性，并非Python语言本身的局限。Jython和IronPython没有GIL。GIL对I/O密集型任务影响较小，因为线程在等待I/O时会主动释放GIL。

第12题：在使用FastAPI开发大模型接口时，中间件和依赖注入分别适合处理什么样的业务逻辑？

核心定位差异： 中间件处理横切关注点（如日志、限流、CORS），依赖注入处理请求上下文准备和资源管理（如鉴权、数据库会话）。

执行顺序： 中间件先于依赖注入执行。中间件可以看作依赖项的超集，依赖项是一种返回可在请求中使用的值的中间件。

维度 中间件 依赖注入
作用范围 全局，所有请求 路由级/函数级
执行顺序 最先执行（LIFO） 在中间件之后
返回值 无（可修改请求/响应） 返回注入的值
适用场景 日志、限流、CORS、请求ID 鉴权、数据库会话、参数校验

中间件适合处理：

  • 日志记录（记录所有请求的进入/离开时间和状态码）
  • 限流和DoS防护
  • CORS配置
  • 请求ID注入和追踪

依赖注入适合处理：

  • 认证和鉴权（从Header解析Token → 查用户 → 校验权限）
  • 数据库会话管理（yield依赖自动清理）
  • 分页参数解析
  • 服务实例注入

分层建议： 全局中间件处理通用功能，路由组依赖注入处理鉴权等，路由内依赖处理特定逻辑。使用API Router注入组级依赖，利用FastAPI默认依赖缓存机制优化性能。

延伸知识点： FastAPI的依赖注入支持四种形态：函数依赖（简单解析）、嵌套依赖（链式逻辑）、类依赖（参数化配置）和yield依赖（资源管理）。中间件注册顺序决定执行顺序（LIFO：最后添加的是最外层）。同一请求中多次调用同一依赖会返回缓存实例。

Python 类型与 dict key 可用性

类型 / 对象 可哈希 可作为 dict key 说明
int ✅ ✅ 不可变；True == 1，所以 True 和 1 会视为同一个 key
float ✅ ✅ 不可变；1 == 1.0，同一个 key；NaN != NaN
bool ✅ ✅ int 子类
complex ✅ ✅ 不可变
str ✅ ✅ 不可变
bytes ✅ ✅ 不可变
None ✅ ✅ 单例
tuple 视元素而定 视元素而定 元素全部可哈希才可，如 (1, "a") ✅，(1, []) ❌
frozenset ✅ ✅ 不可变集合
list ❌ ❌ 可变；可转 tuple
dict ❌ ❌ 可变；可转 frozenset(d.items()) 或 tuple(sorted(d.items()))
set ❌ ❌ 可变；可转 frozenset
bytearray ❌ ❌ 可变；可转 bytes
namedtuple ✅（字段可哈希时） ✅ tuple 子类
enum.Enum ✅ ✅ 枚举成员通常不可变
datetime.date / datetime.datetime / datetime.time / datetime.timedelta ✅ ✅ 不可变
Decimal / Fraction ✅ ✅ 不可变
range ✅ ✅ 不可变序列
函数 / 方法 / 类 / 模块 ✅ ✅ 默认按身份哈希
object() 实例 ✅ ✅ 默认按 id 哈希
普通自定义类（未定义 __eq__） ✅ ✅ 默认按 id 哈希
自定义类（定义 __eq__ 但未定义 __hash__） ❌ ❌ Python 会把 __hash__ 设为 None
自定义类（定义 __eq__ 和 __hash__） ✅ ✅ 需保证：a == b 时 hash(a) == hash(b)
@dataclass(frozen=True) ✅ ✅ 推荐；默认生成 __hash__
@dataclass(frozen=False) 默认 ❌ ❌ 默认 eq=True，__hash__ 为 None
@dataclass(eq=False) ✅ ✅ 保留 object 的身份哈希

判断口诀：dict 的 key 必须可哈希。
可哈希 ≈ 不可变 + 正确实现 __hash__ / __eq__。
不可做 key 时：list -> tuple，set -> frozenset，dict -> frozenset(d.items())，bytearray -> bytes，自定义对象 -> @dataclass(frozen=True) 或实现 __hash__ + __eq__。
